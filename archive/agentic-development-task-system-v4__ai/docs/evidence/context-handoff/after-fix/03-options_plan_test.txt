## Task Brief: Add `divide(a, b)` to calc library

### Request Summary

Add a `divide(a, b)` function to `src/calc.js` that performs standard arithmetic division and throws a clear, descriptive error when the divisor `b` is zero. The implementation must follow the existing style of the other arithmetic functions already present in the file.

---

### Scope

**In scope:**
- Define and export `divide(a, b)` in `src/calc.js`
- Throw a `Error` with a descriptive message when `b === 0`
- Match the code style (function declaration form, export mechanism, naming conventions) of existing functions

**Out of scope:**
- Modifying or refactoring existing functions
- Adding tests (unless a test file already exists and a pattern is established)
- Input validation for non-numeric types (NaN, strings) beyond what other functions do
- Floating-point special cases (Infinity, NaN) beyond the zero check

---

## Acceptance Criteria

| ID | Requirement | Risk (H/M/L) |
|----|-------------|--------------|
| AC1 | `divide(a, b)` is defined in `src/calc.js` and exported consistent with existing exports | L |
| AC2 | `divide(10, 2)` returns `5` (basic integer division) | L |
| AC3 | `divide(7, 2)` returns `3.5` (non-integer quotient returned correctly) | L |

| AC7 | The function signature, declaration style, and export match the pattern of existing functions in `src/calc.js` | L |

---

## Open Assumptions / Interpretation Decisions

1. **Error type** — "throws a clear error" is interpreted as `throw new Error(...)` using a standard JavaScript `Error` object. If the existing codebase uses a custom error class or a different throw pattern, that pattern should be followed instead (AC6 and AC5 still hold for message clarity).

2. **Zero check semantics** — JavaScript's `-0 === 0` evaluates to `true`, so `divide(5, -0)` will also throw under a strict `=== 0` check. This is treated as correct behavior and not a bug. Not called out in the request but covered implicitly by AC5.

3. **Negative numbers** — The request does not mention negative operands. Assumed to work via standard JS division (no special handling needed).

4. **Export style** — Not specified in the request. Assumed to mirror whatever mechanism (`module.exports`, named `export`, etc.) the existing functions use.

5. **Non-numeric inputs** — No mention of guarding against `null`, `undefined`, strings, etc. Assumed out of scope, consistent with the style of existing functions.

6. **No test requirement stated** — The request does not ask for tests. If a test file (e.g., `src/calc.test.js`) already exists, adding corresponding tests would be natural but is treated as out of scope unless confirmed.

## Discovery: Add `divide(a, b)` to `src/calc.js`

### File: `src/calc.js`

The file currently contains three functions, all following an identical pattern:

- **Declaration style**: Named function expression with `export` keyword inline (`export function name(a, b) { ... }`)
- **Export mechanism**: ES Module named exports (`export function ...`) — no `module.exports`, no default export
- **Body style**: Single-expression return, no input validation, no error handling
- **Naming convention**: lowercase verb names (`add`, `subtract`, `multiply`), parameters `(a, b)`

```js
export function add(a, b) {
  return a + b;
}

export function subtract(a, b) {
  return a - b;
}

export function multiply(a, b) {
  return a * b;
}
```

### No test files found

No `*.test.*` files exist anywhere in the working directory, so adding tests is confirmed out of scope per the task brief.

### Implementation plan

The `divide` function should:
1. Use `export function divide(a, b)` — matching the inline named export style
2. Check `if (b === 0)` and `throw new Error("Cannot divide by zero")`
3. Return `a / b` for all other cases
4. Require no other changes to the file

```js
export function divide(a, b) {
  if (b === 0) {
    throw new Error("Cannot divide by zero");
  }
  return a / b;
}
```

This satisfies all seven acceptance criteria (AC1–AC7) and matches the existing style exactly.
