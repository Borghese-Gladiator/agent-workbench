# Normalized feature input

> The cleaned-up version of `raw-idea.md`. Spec-ready input. Each section is
> mandatory — write "N/A" with a one-line reason rather than leaving blank.

## Problem
<!-- One paragraph. What is broken / missing / suboptimal today? Be concrete. -->

## Desired outcome
<!-- One paragraph. What does the world look like after this ships? Observable, not
     mechanism-level. -->

## Users
<!-- Who is affected? Internal teams, external customers, specific personas. -->

## Constraints
<!-- Hard limits: tech, time, security, compliance, dependencies, headcount. -->

## Scope
<!-- What IS in scope for this run. Bullet list. -->

## Non-goals
<!-- What is explicitly NOT being attempted in this run. Bullet list.
     This section prevents scope creep — be ruthless. -->

## Success metrics
<!-- How will we know this worked? Quantitative if possible (latency, conversion,
     error rate). Qualitative is acceptable when measurement is impractical. -->

## Risks
<!-- What could go wrong? Technical, product, organizational. Include the
     mitigation for each, even if it's "accept and monitor". -->

## Open questions
<!-- Anything the spec author cannot answer alone. Tag with @owner if known. -->
