  - **Validator design — hand-rolled walker over a YAML schema (DR-001/002).** The user explicitly left library-vs-hand-roll open. Hand-roll won because (a) adding a real schema lib like pydantic/jsonschema would require introducing a `pyproject.toml` and a packaging story for a project that has neither, (b) the schema is shallow (~50 fields, one nesting level), and (c) the walker landed in ~120 lines. The schema lives in `schemas/run-metadata.yaml`, restructured from the old descriptive shape into a uniform `{type, required, enum, eq, keys, free_form}` per-field shape consumed by a new `_validate_against_schema(data, schema)` in `lib/metadata.py`. Each field tracks one or more accepted type tokens (`str | int | bool | dict | list | null`, union as a list) and the walker emits a typed `Problem(path, code, message)` dataclass instead of failing fast — one load reports every issue, not the first. `scope` and `artifacts` are tagged `free_form: true` per the brief's non-goal and only checked for "is a dict"; `build` is `required: false` (the legacy `2026-05-18-poker` run predates the block); `target.repo.base_ref_sha` is `required: false` (added 2026-05-23 to existing runs lazily). One subtle correctness fix: the `int` type token explicitly excludes `bool` (Python's `bool` is a subclass of `int`), so a `validation.known_issues_count = True` slip is caught instead of silently passing.
  - **Warn vs strict (DR-004).** A new `policies.metadata_validation` key in `agent-workbench.yaml` selects mode (`warn` default, `strict` opt-in). Default-mode philosophy: every real violation (missing required, wrong type, enum, eq) prints one line per problem to stderr prefixed with the `run_id` and the dot-path of the bad field; **unknown extra keys are silent** — they're the additive-backcompat path. Strict mode raises `MetadataError` joining every problem, *including* unknown keys (typo-catching mode). An unrecognized `metadata_validation` value falls back to warn with a one-line stderr note so a typo doesn't silently disable strict. The duplicate-file integrity check (above) is always-on; mode doesn't gate it. The Python constants `STATUSES` and `REQUIRED_TOP_LEVEL` stayed in `lib/metadata.py` (transitions.py + a few cmd_*.py read them) but are now asserted equal at module-import time to the schema-derived sets — drift will fail loudly the next time someone adds a status to one place without the other.
