# v0.0.9 — Activity Tab + WebSocket Live Updates

## Brief

Upgrade the Activity tab to its final form: a split view showing running agents
as cards and a real-time timeline of actions. Add WebSocket infrastructure for
push-based updates across the entire app (board, epics, activity).

---

## Design

### Activity Tab Layout
```
+------------------------------------------+
| Activity                                 |
+------------------------------------------+
| [Running Agents]            [Timeline]   |
|                                          |
| +--------+ +--------+      | 12:03 agent |
| | Agent1 | | Agent2 |      |  created X  |
| | task.. | | task.. |      | 12:02 user  |
| | 2m ago | | 5m ago |      |  moved Y    |
| +--------+ +--------+      | 12:01 ...   |
|                             |             |
+------------------------------------------+
```

### Left Panel — Running Agents (card list)
- Cards for each agent with `state = 'running'` terminal sessions
- Each card shows: agent name, current work item, session duration, last action
- Click card -> focus that terminal session in the terminal panel
- Cards auto-appear/disappear as sessions start/stop

### Right Panel — Action Timeline
- Chronological feed of activity_events (newest first)
- Auto-scrolls as new events arrive via WebSocket
- Each entry: timestamp, actor, action, entity link
- Filter by: entity type, agent, time range
- Color-coded by event category (create=blue, update=yellow, complete=green, fail=red)

## Changes

### Phase 1: WebSocket Infrastructure
1. Create `src/server/ws/index.ts` — WebSocket server setup
   - Upgrade handler on `/ws/events`
   - Client registry (track connected clients)
   - Broadcast helper: `broadcast(channel, payload)`
2. Create `src/server/ws/channels.ts` — event channels
   - `activity` — new activity_events
   - `work_items` — status changes, creates
   - `sessions` — terminal session state changes
   - `agents` — agent status changes
3. Hook into repositories: after INSERT/UPDATE, broadcast to relevant channel
4. Mount in `src/server/index.ts` alongside HTTP server

### Phase 2: Client — WebSocket Hook
1. Create `src/client/services/ws.ts` — WebSocket client singleton
   - Auto-reconnect with backoff
   - Subscribe/unsubscribe by channel
   - `useWebSocket(channel, callback)` hook
2. Integrate with TanStack Query — invalidate queries on WS messages
   - `work_items` channel -> invalidate `['work-items']` queries
   - `activity` channel -> invalidate `['activity']` queries

### Phase 3: Activity Tab
1. Rewrite `ActivityPage.tsx` as split-panel layout
2. Create `RunningAgentCards.tsx` — live agent card list
   - Query terminal sessions where state = 'running'
   - Join with agents + work_items for display data
   - Subscribe to `sessions` WS channel for live updates
3. Create `ActionTimeline.tsx` — streaming event timeline
   - Initial load: last 50 events via REST
   - New events: prepended via `activity` WS channel
   - Auto-scroll toggle (pause when user scrolls up)
   - Entity type filter chips

### Phase 4: Live Updates Everywhere
1. Board tab: cards update in real-time when status changes via WS
2. Epics tab: progress bars update live
3. Terminal panel: session state indicators update live

## Tests

### Unit
- WebSocket broadcast: message reaches all subscribed clients
- WebSocket reconnect: client reconnects after disconnect
- Activity event rendering: correct icon/color per event type
- Agent card: shows correct session data

### Manual
1. Open Activity tab -> see running agent cards (if any sessions active)
2. Create a work item from terminal -> event appears in timeline instantly
3. Transition a work item on board -> event appears in activity timeline
4. Open two browser tabs -> both see live updates
5. Kill server, restart -> WebSocket reconnects automatically
6. Scroll up in timeline -> auto-scroll pauses; click "Jump to latest" resumes
