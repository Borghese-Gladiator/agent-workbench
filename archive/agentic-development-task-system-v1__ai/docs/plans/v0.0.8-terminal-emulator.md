# v0.0.8 — Terminal Emulator (tmux-backed)

## Brief

Add a terminal emulator to the UI built on top of tmux. This enables the core
interaction pattern: "start typing in a terminal and create story/task/bug."
The terminal is a dedicated tab (`/terminal`) — a full-page terminal experience
with session tabs along the top.

---

## Design

### Architecture
```
Browser (xterm.js)  <--WebSocket-->  Express WS  <--pty.js-->  tmux session
```

- **xterm.js** renders the terminal in the browser
- **node-pty** spawns a shell attached to a tmux session
- **WebSocket** (`/ws/terminal/:sessionId`) streams stdin/stdout
- **tmux** provides session persistence, multiplexing, and Agent Teams support

### Why tmux
- Agent Teams already uses tmux for multi-agent coordination
- Sessions survive server restarts (reattach)
- Multiple panes/windows per session
- Named sessions for easy identification

### Terminal Tab (`/terminal`)
- Full-page terminal view — takes up the entire content area
- Session tab bar across the top for multiple tmux sessions
- Each tab = one tmux session
- "+" button to create new session
- Active session fills the remaining vertical space

### Quick-Create from Terminal
- Type a magic prefix in the terminal to create work items:
  - `//story Fix the login flow` -> creates a story with that title
  - `//task Update dependencies` -> creates a task
  - `//bug Crash on empty input` -> creates a bug
- The server intercepts these via a simple stdin line parser
- Created items appear on the board immediately

## Changes

### Phase 1: Dependencies
1. Add `node-pty`, `xterm`, `@xterm/addon-fit`, `@xterm/addon-web-links`, `ws`
2. Add tmux detection/validation on server startup

### Phase 2: Server — WebSocket + PTY
1. Create `src/server/terminal/manager.ts` — tmux session lifecycle
   - `createSession(name)` -> `tmux new-session -d -s <name>`
   - `attachSession(name)` -> spawn `node-pty` attached to `tmux attach -t <name>`
   - `listSessions()` -> parse `tmux list-sessions`
   - `killSession(name)` -> `tmux kill-session -t <name>`
2. Create `src/server/terminal/ws-handler.ts` — WebSocket upgrade handler
   - On connect: attach to tmux session via pty
   - Stream pty stdout -> ws
   - Stream ws -> pty stdin
   - Intercept `//` prefix lines for quick-create
3. Create `src/server/routes/terminal.ts` — REST endpoints
   - `GET /api/terminal/sessions` — list tmux sessions
   - `POST /api/terminal/sessions` — create new tmux session
   - `DELETE /api/terminal/sessions/:name` — kill session
4. Mount WebSocket handler in `src/server/index.ts`

### Phase 3: Client — Terminal Page
1. Create `src/client/pages/TerminalPage.tsx` — full-page terminal view
   - xterm.js instance per session tab
   - WebSocket connection management
   - Resize handling with @xterm/addon-fit
   - Session tab bar across top (create, switch, close)
2. Create `src/client/components/TerminalSessionBar.tsx` — tab strip for sessions
3. Wire up route in `router.tsx` (replace placeholder from v0.0.7)

### Phase 4: Session Tracking
1. Update `terminal_sessions` table — link to tmux session names
2. Auto-create `terminal_session` DB record when tmux session created
3. Auto-update state on disconnect/exit
4. Link terminal sessions to work items when `//` commands used

## Tests

### Unit
- tmux manager: create/list/kill sessions
- `//` prefix parser: story, task, bug extraction
- WebSocket message framing

### Manual
1. Click Terminal tab -> full-page terminal view
2. Click "+" -> new terminal session appears as a tab
3. Type commands -> shell works normally
4. Type `//task My new task` -> work item appears on board
5. Close browser, reopen -> terminal reconnects to existing tmux session
6. Multiple session tabs work independently
7. Switch between session tabs -> each preserves its own state
