# v0.4.0 — Orchestration parity

## Brief

Comparison against ComposioHQ/agent-orchestrator (v0.2.5) surfaced four architectural gaps that, closed together, move this project from "task tracker with a terminal" to "single-user orchestrator." This plan addresses the four highest-leverage gaps only. Multi-project, plugin boundary, CLI expansion, observability, and notifications are deferred to v0.5.x.

Gaps addressed here:

1. **Worktree isolation per session** — one git worktree per running session, so parallel Claude Code sessions can't stomp each other.
2. **Optional PR linking** — opt-in link from a work item to a real GitHub PR; surface PR number, CI status, and review state in the board and detail view. Every work item can be linked and unlinked at will. Nothing is auto-linked without consent.
3. **`needs_input` flag on sessions** — a single boolean that surfaces "this session is waiting on a prompt" as a glanceable dot. Detected by regex-matching known Claude Code prompt strings against recent pty output.
4. **Reaction hook** — when CI turns red or a review comment is requested on a *linked* PR, auto-generate a comment on the work item (same pattern as v0.3.3 adversarial-review), with an optional auto-paste to the linked session.

Explicit non-goals for v0.4.0:
- Multi-project. Single implicit project stays.
- Plugin system. Claude Code + tmux stay hard-coded; we add a thin `scm/` seam for GitHub only.
- No `ao`-style CLI. Ingest CLI stays the only CLI surface.
- No Slack/desktop notifiers.

## Changes

### 1. Worktree isolation (gap #1)

New repo: `src/server/workspace/worktrees.ts`.

- Configurable `WORKTREE_ROOT` env (default `data/worktrees/`).
- `createWorktree(sessionId, branchName, baseRef)` → shells out to `git worktree add <root>/<sessionId> -b <branchName> <baseRef>`. Returns absolute path.
- `removeWorktree(sessionId)` → `git worktree remove --force` + cleanup row.
- New table `session_worktrees`:
  - `session_id` (FK, unique)
  - `path` (absolute)
  - `branch_name`
  - `base_ref`
  - `created_at`

Wire-up:
- `POST /api/sessions/` takes optional `create_worktree: true` (default) + `base_ref` (default `main`). When true, create worktree before spawning pty; pty's `cwd` is the worktree path.
- Session archive path (`DELETE /api/sessions/:id`) removes the worktree. Guard: skip removal if `git status --porcelain` is non-empty; surface a "dirty worktree" error and require `?force=true`.
- Terminal page `SessionInfoBar` shows worktree path instead of raw cwd when one exists.

Migration `003_session_worktrees.sql` creates the table.

### 2. Optional PR linking (gap #2)

PR linking is **opt-in per work item**. A work item never gets a PR attached without an explicit user action (either a manual link or an explicit toggle to auto-discover from its branch). Linked PRs can be unlinked at any time, which nulls all PR state and silently disables the reaction hook for that item.

New module `src/server/scm/github.ts`:

- Thin wrapper over `gh` CLI (shell out, parse JSON). No Octokit dependency for v0.4.0 — matches AO's "no heavy SDK" ethos.
- `getPr(prNumber)` → `{ number, url, state, isDraft, mergeable, headSha } | null`.
- `findPrByBranch(branchName)` → same shape; used only when auto-link is enabled.
- `getChecks(prNumber)` → `{ overall: 'pending'|'success'|'failure', checks: [{ name, status, conclusion }] }`.
- `getReviews(prNumber)` → `{ state: 'pending'|'changes_requested'|'approved', reviewers: [...] }`.

New columns on `work_items` (migration `004_work_item_pr.sql`):
- `pr_number INTEGER NULL`
- `pr_url TEXT NULL`
- `pr_state TEXT NULL` — `open|merged|closed`
- `ci_state TEXT NULL` — `pending|success|failure`
- `review_state TEXT NULL` — `pending|changes_requested|approved`
- `pr_last_synced_at TEXT NULL`
- `pr_auto_link BOOLEAN DEFAULT 0` — when true, poll loop is allowed to auto-discover a PR from `branch_name` and set `pr_number` if still null. When false, only explicit `link-pr` calls populate PR state.

Routes:
- `POST /api/work-items/:id/link-pr` — body `{ pr_number }`. Validates the PR exists via `getPr`, sets `pr_number` + `pr_url`, immediately syncs CI/review state. Writes `activity_event` of type `pr_linked`.
- `DELETE /api/work-items/:id/pr-link` — nulls `pr_number`, `pr_url`, `pr_state`, `ci_state`, `review_state`, `pr_last_synced_at`. Leaves `pr_auto_link` alone (unlinking ≠ disabling auto-link; user decides separately). Writes `activity_event` of type `pr_unlinked`.
- `PATCH /api/work-items/:id` accepts `pr_auto_link` toggle.
- `POST /api/work-items/:id/sync-pr` — manual refresh button. No-op (with a clear 4xx) if `pr_number` is null.

Sync strategy:
- On-demand: `POST /api/work-items/:id/sync-pr`.
- Poll loop every 60s, two passes:
  1. Items with `pr_number` set → refresh CI/review/state fields.
  2. Items with `pr_auto_link=1`, `pr_number` null, `branch_name` set, status in (`in_progress`, `in_review`) → `findPrByBranch`; if found, link it (same path as explicit link).
- No webhooks in v0.4.0. Poll is sufficient for single-user scale.

UI:
- `WorkItemDetailPage` adds a "PR" panel:
  - When unlinked: shows a "Link PR" button. Clicking opens a small dialog with (a) a number input, (b) a "Find from branch `<branch>`" button if `branch_name` is set, and (c) a checkbox for `pr_auto_link` (default off).
  - When linked: shows PR number as a link out, state/CI/review dots, "Sync now" button, and an "Unlink" button. Unlink confirms before nulling columns.
- `BoardPage` cards show a small PR badge (`#1234`) only when `pr_number` is set; CI dot (green/amber/red) only when `ci_state` is set. Items with no PR look exactly as they do today.

### 3. `needs_input` flag on sessions (gap #3)

Narrow, single-purpose version. The problem: `terminal_sessions.state='running'` can't distinguish "Claude is generating code" from "Claude is blocked on a `[y/n]` prompt you forgot to answer." Solve just that, nothing else.

Migration `005_session_needs_input.sql`:
- Add `terminal_sessions.needs_input BOOLEAN DEFAULT 0`.
- Add `terminal_sessions.needs_input_detected_at TEXT NULL`.

Detection:
- `src/server/terminal/needs-input-probe.ts` — every 15s for every session with `state='running'`:
  - Pull the last ~4 KB of pty output (reuse the ring buffer already maintained by ws-relay).
  - Match against a small curated list of Claude Code prompt strings: `"Do you want to proceed"`, `"Do you want to"`, `"[y/n]"`, `"(y/n)"`, `"Continue?"`, `"Would you like to"`. Kept as an exported array so new prompts can be added in one place.
  - On match: set `needs_input=1`, `needs_input_detected_at=now()`, write `activity_event` of type `session_needs_input`. No-op if already true.
  - On next probe with no match in the tail (implying user answered or new output scrolled the prompt away): clear `needs_input=0`.
- No pid probing, no lifecycle split, no confidence levels, no separate `activity_state`. Roughly 50–80 lines plus tests.

UI:
- `SessionInfoBar` and terminal tab render an amber dot when `needs_input=1`.
- Kanban cards for work items whose `active_session_id` points at a `needs_input` session render the same amber dot. This is the glanceable "this needs you" signal.
- No animation; a static dot is enough.

### 4. Reaction hook (gap #4)

New module `src/server/domain/reactions.ts`:

- Called from the PR poll loop. Only fires for work items with a linked PR (`pr_number` non-null). Unlinking a PR disables reactions for that item without further config.
- Given a work item and the newly-synced PR state:
  - If `ci_state` transitioned `pending → failure`: render a system comment with a "fix CI" prompt template (includes failing check names + log URL via `gh run view`), mirroring v0.3.3's adversarial-review comment pattern.
  - If `review_state` transitioned `pending → changes_requested`: render a system comment with the review comments inlined + a "respond to review" prompt template.
- Comments authored by new constants `CI_REACTION_BOT_ID`, `REVIEW_REACTION_BOT_ID`.
- Same Copy / Send-to-terminal actions as v0.3.3 — reuses `CommentList` bot-comment rendering. No new UI code beyond adding the two bot IDs to the recognized-bot set.
- Config flag on `work_items`: `auto_paste_reactions BOOLEAN DEFAULT 0`. When true and `active_session_id` is set, the server pastes the rendered prompt into the session automatically (still no auto-Enter — user still reviews + submits).

`PATCH /api/work-items/:id` accepts `auto_paste_reactions` (and `pr_auto_link` from gap #2).

Activity log: new event types `ci_reaction_generated`, `review_reaction_generated`, `reaction_auto_pasted`, `pr_linked`, `pr_unlinked`.

## Tests

### Unit

- `src/server/workspace/worktrees.test.ts`
  - `createWorktree` shells with correct args (mock child_process).
  - `removeWorktree` refuses when worktree dirty, succeeds with `force=true`.
- `src/server/scm/github.test.ts`
  - Parse `gh pr view --json` output into our shape for: no PR, draft, open, merged.
  - Parse `gh pr checks --json` into overall state (all-pass → success, any-fail → failure, any-pending & no-fail → pending).
- `src/server/routes/work-items.pr-link.test.ts`
  - `link-pr` validates PR exists before setting columns; rejects unknown PR number.
  - `pr-link DELETE` nulls all six PR columns and leaves `pr_auto_link` unchanged.
  - Poll loop's auto-link pass is skipped when `pr_auto_link=0` even if branch matches an open PR.
  - `sync-pr` returns 4xx when no PR is linked.
- `src/server/domain/reactions.test.ts`
  - Given previous and next PR state, returns correct reaction type or null.
  - Renders CI reaction template with failing check names substituted.
  - Does not fire when transition is non-regressive (e.g. failure → pending).
  - Does not fire for work items with `pr_number=null` (unlinked).
- `src/server/terminal/needs-input-probe.test.ts`
  - Regex matches each curated Claude Code prompt string. Parametrize across all entries in the prompts array.
  - Buffer tail with no matching prompt leaves `needs_input=0`.
  - Matching buffer flips flag to 1 and sets `needs_input_detected_at`; subsequent non-matching buffer flips it back to 0.

### E2E

- Extend `tests/e2e-ingest.ts`: ingest a work item with `branch_name` set, start a session with `create_worktree=true`, assert worktree exists on disk + DB row created.
- New `tests/e2e-pr-link.ts`: stub `gh` binary via `PATH` override to return canned JSON.
  - Call `link-pr`; assert all six PR columns set, `pr_linked` activity event written.
  - Call `sync-pr`; assert columns refresh.
  - Call `DELETE /pr-link`; assert all six columns null, `pr_unlinked` activity event written, `pr_auto_link` unchanged.
  - Toggle `pr_auto_link=1`, run a poll tick, assert PR auto-discovered from branch.
- New `tests/e2e-reactions.ts`: same stub, simulate `pending → failure` transition between two sync calls on a *linked* item; assert CI reaction system comment + `ci_reaction_generated` activity event. Repeat with an unlinked item; assert no comment fires.

### Manual (browser)

Required verification pass before cutting v0.4.0:

- Create a work item with `branch_name=test-branch`. Start a session with "create worktree" checked. Confirm session's cwd is the worktree path in `SessionInfoBar`.
- On the work item detail, click "Link PR", enter a PR number, confirm the PR panel populates. Click "Unlink"; confirm panel reverts to the "Link PR" button and the card PR badge disappears.
- Push a commit, open a draft PR on GitHub against the test branch. On a different work item, toggle `pr_auto_link` on; within 60s confirm the PR auto-links.
- Force a CI failure on a linked PR. Wait ≤60s. Confirm a CI reaction system comment appears on the work item with Copy + Send-to-terminal buttons.
- Unlink the PR, force another CI transition. Confirm no new reaction comment is created.
- Toggle `auto_paste_reactions` on. Re-link, trigger another failure. Confirm the prompt is pasted into the linked session's pty without Enter.
- In a linked session, trigger a Claude Code confirmation prompt (e.g. an edit that requires `[y/n]`). Within 15s confirm the amber `needs_input` dot appears on the session info bar and on the work item's Kanban card. Answer the prompt; within 15s confirm the dot clears.

## Rollout

- Single PR. Migrations 003–005 run idempotently on startup; existing `state` values map 1:1 to `lifecycle_state`.
- No feature flag. This is a dev tool for one user; gate-free ships are fine.
- Version bump: 0.3.3 → 0.4.0 (minor — schema migrations, new columns, new routes).
- README diff: add a "Worktrees & PRs" section under the v0.3.3 terminal section. Document the `gh` CLI dependency.
