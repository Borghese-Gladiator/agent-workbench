# v0.0.7.1 — UI Polish & Interaction Refinements

## Brief

Improve the Board, Epics, Library, and Activity tabs with clickable cards,
inline editing, better visual design, and a reworked Library that shows the full
epic/story hierarchy with markdown plan previews.

---

## Changes

### 1. Board — Clickable work item cards

Cards on the kanban board open a detail slide-over panel (right side drawer)
when clicked. The panel shows:
- Title, kind, status, assigned agent
- Body / description (markdown rendered)
- Acceptance criteria
- Sub-items list
- Reviews
- Close button to dismiss

**Files:**
- Create `src/client/components/WorkItemDrawer.tsx` — slide-over detail panel
- Update `src/client/pages/BoardPage.tsx` — add selectedItemId state, render drawer

### 2. Board — Kind icons instead of badges

Replace the `StatusBadge` for `kind` with inline icons before the title:
- story → `BookOpen` (blue)
- task → `CheckSquare` (gray)
- bug → `Bug` (red)

Remove the kind badge from the card body. The icon sits left of the title text.

**Files:**
- Update `src/client/pages/BoardPage.tsx` — `WorkItemCard` component

### 3. Board — Group by epic

Add a "Group by" toggle in the filter bar: `None` (default, current behavior)
or `Epic`. When grouped by epic:
- Each epic gets its own horizontal swim lane (a row of columns)
- Lane header shows epic title + progress
- Items with no epic go in an "Ungrouped" lane at the bottom

**Files:**
- Update `src/client/pages/BoardPage.tsx` — add groupBy state, EpicLane component

### 4. Board — Remove priority from cards

Remove the priority `StatusBadge` from work item cards. Priority is still stored
in the data model and visible in the detail drawer, just not on the card face.

**Files:**
- Update `src/client/pages/BoardPage.tsx` — `WorkItemCard` component

### 5. Epics — Inline editing

- Epic titles become editable on click (contentEditable or input swap)
- "Create Epic" button at top of the page
- When creating, user picks an initiative (or "None") from a dropdown
- Epic status is changeable via a dropdown on the row

**Files:**
- Update `src/client/pages/EpicsPage.tsx` — add inline edit, create form
- Update `src/client/services/hooks.ts` — add `useUpdateEpic` if missing

### 6. Activity — Move agents list here

Move the agent cards from Library into the Activity tab as a top section.
The Activity tab becomes a split layout:
- Top: horizontal scrollable agent cards (same as current Library agents section)
- Bottom: activity timeline (existing)

**Files:**
- Update `src/client/pages/ActivityPage.tsx` — add agent cards section at top
- Update `src/client/pages/LibraryPage.tsx` — remove agents section

### 7. Library — Epic tree with plan previews

Completely rework Library into a hierarchy browser:

```
+--------------------------------------------+
| Library                                    |
+------------------+-------------------------+
| [Tree Panel]     | [Preview Panel]         |
|                  |                         |
| ▼ Epic A         | ## Story: Build login   |
|   ▸ Story 1     |                         |
|   ▸ Story 2     | ### Plans               |
|   ▼ Story 3     | [Plan 1] [Plan 2]       |
|     └ Plan.md   |                         |
| ▸ Epic B        | (rendered markdown)     |
| ▸ Ungrouped     |                         |
+------------------+-------------------------+
```

**Left panel — Tree:**
- Epics as top-level collapsible nodes
- Stories/tasks/bugs as children (with kind icon)
- Under each story: any artifacts of type `note` or `file` with `.md` extension
  (these are the "plans")
- "Ungrouped" section for items with no epic
- Click a story → show its details in the preview
- Click a plan → show the plan markdown in the preview

**Right panel — Preview:**
- When a story is selected: title, body, status, acceptance criteria
- Below that: list of plan artifacts as clickable tabs/chips
- When a plan is clicked: render its content as markdown
- If no plans exist: show "No plans generated for this story"

**Data:** Plans are `artifacts` rows where `artifact_type = 'note'` or
`artifact_type = 'file'` and path ends in `.md`, linked via `work_item_id`.
The artifact `metadata_json` or a new dedicated content field stores the
markdown. For now, the plan content is stored in `metadata_json` as
`{ "content": "..." }`.

**Files:**
- Rewrite `src/client/pages/LibraryPage.tsx` — tree + preview split layout
- Create `src/client/components/EpicTree.tsx` — collapsible tree component
- Create `src/client/components/PlanPreview.tsx` — markdown renderer panel
- Update `src/client/services/hooks.ts` — add `useArtifactsForWorkItem` hook
- Update `src/server/routes/work-items.ts` — include artifacts in GET /:id response
