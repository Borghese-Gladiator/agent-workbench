# Repo Structure Plan (v0.0.1)

This plan restructures the repository to support AI-native development with AGENTS.md files, skills, hooks, and progressive documentation.

---

## Motivation

The repo has no structured guidance for AI agents. Plans live loose in `docs/`, there's no AGENTS.md, no skills, no hooks, and no local guardrails near complex modules. This makes every AI session start from scratch.

## Goals

1. Add `AGENTS.md` as the north star file (short, scannable)
2. Add local `AGENTS.md` files near sharp edges (`src/server/`, `src/client/`)
3. Organize docs into `docs/plans/`, `docs/adr/`, and `docs/architecture.md`
4. Create `.claude/skills/` for reusable workflows
5. Prepare for `.claude/settings.json` hooks (guardrails)

## Changes

### 1. Root `AGENTS.md`
- Purpose, repo map, rules, commands
- Target: under 80 lines

### 2. Local `AGENTS.md` files
- `src/server/AGENTS.md` — DB access patterns, migration rules, ingest conventions
- `src/client/AGENTS.md` — API call patterns, data fetching, styling conventions

### 3. Documentation reorganization
- Move plan docs into `docs/plans/`
- Rename with consistent versioning:
  - `v0.0.2_plan__chatgpt.md` (core product spec)
  - `v0.0.3_plan_phases__claude_code.md` (implementation phases)
  - `v0.0.4_plan__issue_editing_and_dnd.md` (UI polish)
  - `v0.0.5_plan__claude_code.md` (expanded vision)
- Create `docs/architecture.md` (extracted from README)
- Create `docs/adr/` for future Architecture Decision Records

### 4. Skills directory
- Create `.claude/skills/` (empty, ready for skills)
- Starter skill candidates:
  - Adding a new DB table + repository
  - Adding a new API route end-to-end
  - Debugging ingest pipeline issues

### 5. Hooks (deferred — needs user input)
- `.claude/settings.json` will define guardrails
- Proposed hooks to be discussed before implementation
