# v0.3.2 — Replace Agent Cards with Session Cards

## Brief

The "agent cards" on the ActivityPage display static database entries (planner/executor/reviewer roles) with computed status derived from work item assignments. There are no real processes behind them — the actual unit of work is a Claude Code terminal session backed by tmux. This change replaces the agent cards with session cards that reflect real session state, and removes the agent dashboard code that powered the old cards.

### Motivation

- The `agents` table models autonomous workers that don't exist — Claude Code is interactive, not headless
- The real primitive is the `TerminalSession`: it has lifecycle (starting/running/exited/disconnected/archived), a tmux process, and a resumable Claude session ID
- Users need to see their active sessions at a glance and navigate to them quickly

---

## Design

### Session Card — Collapsed State

Each non-archived `TerminalSession` renders as a card in a wrapping grid (replaces the current horizontal-scroll agent card row).

**Layout:** `flex flex-wrap gap-3`. Cards have a fixed min-width (~12rem) and grow to fill available space. On mobile (<640px), cards stack to full-width single column. On wider screens, cards sit side-by-side and wrap naturally.

**Displays:**
- **State indicator** — colored dot: green (running), yellow (starting), red (exited), gray (disconnected)
- **Work item title** — primary text, truncated (from new `workItemTitle` field on session response)
- **Session title** — secondary text, shown if it differs from work item title
- **Time info** — "Started 2h ago" (from `startedAt`) for running/starting sessions; "Inactive for 15m" (from `exitedAt`, falling back to `lastSeenAt`) for exited/disconnected sessions
- **Expand chevron** — bottom-right of the collapsed card, a small `ChevronDown` icon (rotates to `ChevronUp` when expanded)

**Interaction:** Clicking anywhere on the card toggles expand/collapse.

### Session Card — Expanded State

Expanding a card reveals additional detail:

- **Branch name** — e.g., `feat/add-login` (from `session.branchName`)
- **Working directory** — truncated `cwd` path
- **Exit code** — only shown for exited sessions (e.g., "Exited (0)" or "Exited (1)")
- **Session ID** — read-only display of `session.id` (for reference/debugging)
- **"Open Terminal" button** — navigates to `/terminal?session={id}`

**Resume-on-open:** When clicking "Open Terminal" on an exited/disconnected session that has a `claudeSessionId`, the system calls `POST /api/sessions/{id}/resume` before navigating. This makes resumption implicit — no separate Resume button.

### Data Flow

```
ActivityPage
    │
    ├── useSessions() ──> GET /api/sessions (polls every 5s, already exists)
    │       │
    │       └── Response now includes `work_item_title` per session (new LEFT JOIN)
    │
    ├── Filter: exclude archived sessions (client-side)
    │
    └── Render: SessionCard[] (collapsed/expanded)
            │
            └── "Open Terminal" click:
                    ├── if exited/disconnected + claudeSessionId → resumeSession.mutate(id)
                    └── navigate('/terminal?session={id}')
```

## Addendum — What Was Actually Implemented

This section records the delta between the original plan above and the shipped implementation.

### Added during implementation

**Tmux liveness reconciliation in `GET /api/sessions`:**

Added a liveness check to the sessions list endpoint. After fetching rows from SQLite, the route calls `tmux.listSessions()` once (cheap — a single `tmux list-sessions` call) and collects the set of live tmux session names. For every session whose DB state is `running` or `starting` and whose `tmux_session_name` is not in the live set, the route flips the state to `disconnected` (both in the DB via `updateSession` and in the response payload).

Reasoning: the original plan trusted `session.state` as-is, but that value only gets updated when a WebSocket is actively attached to the session (via the PTY `onExit` handler). Sessions that died because tmux was killed externally, the machine rebooted, or any other non-PTY path were left showing a stale `running` state. The reconciliation closes that gap for the list endpoint. Since the client polls `/api/sessions` every 5s, dead sessions self-correct within one poll cycle.

**File:** `src/server/routes/sessions.ts` — added the reconciliation block inside the `GET /` handler.

### Clarifications / minor deviations

- **Version bump**: plan said "0.7.3 → 0.7.4" in Step 4, but the actual `package.json` was at `0.3.1` (the 0.7.x number came from an earlier source-of-truth mismatch during planning). Bumped `0.3.1 → 0.3.2` as agreed.
- **`Bot` icon import** was not present in the ActivityPage at implementation time (the full page was rewritten), so there was no explicit removal — the new imports just exclude it.
- **Exit code label**: cards show just the number (e.g., `0`, `1`) under an "Exit:" label rather than the "Exited (0)" phrasing from the plan. Shorter, same information.
- **`SessionListRow` type** added to `sessions.ts` repo (extends `SessionRow` with `work_item_title`) so `listSessions` has a typed return that includes the JOINed column.

## TODO — Follow-up Work

Known gaps that remain after v0.3.2:

- **PTY exit path still only fires when a WebSocket is attached.** The tmux liveness check added in this version catches sessions that are gone (tmux killed externally, reboot, etc.) and flips them to `disconnected`. It does **not** detect sessions that crashed cleanly with a specific exit code — those still need the PTY `onExit` handler in `ws-relay.ts` to set `state: "exited"` with the actual `exit_code`. Today, if a Claude process exits while nobody is watching, the session will show as `disconnected` (no exit code) instead of `exited (N)`. Consider a background PTY observer that stays attached without a WebSocket client, or a reconciliation pass that captures exit codes via `tmux list-panes -F '#{pane_dead},#{pane_dead_status}'`.

- **`ws-relay.ts:98–102` sends `state: "exited"` to the client the moment it detects a Claude session ID match.** That appears to be incorrect — detecting a `claude --resume <id>` token in the output means Claude just started, not that it exited. This is a pre-existing bug, not introduced by v0.3.2, but worth fixing.

- **The `starting` state is defined in the enum but never written anywhere.** Either start writing it (e.g., after `insertSession` but before the 2s `setTimeout` that pastes the prompt) or remove it from the enum.

- **`assignedAgentId` / `reviewerAgentId` on work items are now fully unused** but still exist on the schema and in some seed/ingest paths. Safe to leave, but a future cleanup could drop them.

- **`agents` table and its CRUD routes are also effectively unused** now that the dashboard is gone. Leaving them for now in case other parts of the app (seeding, tests, ingest) still reference them; audit and remove in a follow-up.

- **State-filtered queries bypass the reconciliation.** `GET /api/sessions?state=running` runs the SQL filter first, so a dead-but-DB-says-running session will be returned and reconciled in the same request, but a caller asking for `state=disconnected` won't see sessions that should have been reconciled *to* disconnected. Acceptable for current callers (ActivityPage fetches all and filters client-side), but worth knowing.
