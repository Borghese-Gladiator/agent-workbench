# v0.3.0 — Task Ingestion (CLI + Claude Skills)

## Brief

Build a CLI tool (`scripts/ingest.ts`) and Claude Code skills (`.claude/skills/`) that let users create tasks, bugs, and epics directly from a Claude Code session. The CLI generates properly-formatted ingest JSON envelopes and drops them into `.taskboard/inbox/` — the existing Chokidar watcher picks them up, validates via Zod, and processes them through the standard pipeline. No new server code needed.

### User stories

1. **As a user in Claude Code**, I can invoke `/create-task` to generate a task (defaults: kind=`task`, status=`triage`)
2. **As a user in Claude Code**, I can invoke `/create-task --bug` to generate a bug
3. **As a user in Claude Code**, I can invoke `/create-epic` to generate an epic
4. **When a new task lands in Triage on the board**, I click "Start Session" which opens the terminal tab with a Claude session (already implemented in v0.2.0)

## Design

### Architecture

```
Claude Code skill ──invokes──> scripts/ingest.ts ──writes JSON──> .taskboard/inbox/
                                                                       │
                                                                       ▼
                                                      Chokidar watcher (existing)
                                                                       │
                                                                       ▼
                                                      validator.ts → processor.ts → SQLite
```

The CLI is the single entry point for programmatic task creation. Skills are thin wrappers that invoke the CLI. This keeps the logic in one place and makes the CLI independently useful outside of Claude Code (e.g., from other scripts, hooks, or the terminal).

### Why a CLI, not a direct API call

1. **Reuses the existing ingest pipeline** — validation, dedup (SHA-256), activity logging, file audit trail all come for free
2. **Works offline / without the server running** — JSON files queue up in `inbox/` and get processed when the server starts
3. **Auditable** — every created entity has a corresponding JSON file in `.taskboard/processed/`
4. **Skill-friendly** — Claude Code skills can invoke CLI tools via Bash; they cannot make HTTP calls reliably

### CLI design

Single script: `scripts/ingest.ts` with subcommands via positional args.

```
npx tsx scripts/ingest.ts task --title "Fix login bug" --body "Details..." --kind bug --epic-id <uuid>
npx tsx scripts/ingest.ts epic --title "Auth overhaul" --description "Rework auth layer"
```

Output: the path of the generated JSON file + the generated entity UUID, printed to stdout for the skill to capture.

## Changes

### Phase 1: CLI tool — `scripts/ingest.ts`

**New file: `scripts/ingest.ts`**

A standalone Node/TypeScript script (no new dependencies — uses `uuid` and `zod` already in the project).

```typescript
// Usage:
//   npx tsx scripts/ingest.ts task [options]
//   npx tsx scripts/ingest.ts epic [options]

// Subcommand: task
//   --title <string>          (required) Task title
//   --body <string>           Task body / description (default: "")
//   --kind <task|bug>         Work item kind (default: "task")
//   --status <status>         Initial status (default: "triage")
//   --epic-id <uuid>          Link to an epic
//   --parent-id <uuid>        Parent work item (for subtasks)
//   --tags <tag1,tag2>        Comma-separated tags
//   --acceptance-criteria <s>  Acceptance criteria text
//   --branch-name <string>    Git branch name
//   --assigned-agent-id <s>   Assigned agent ID
//   --actor-id <string>       Who is creating this (default: "claude-code")
//   --actor-type <string>     Actor type (default: "agent")
//   --source <string>         Source identifier (default: "claude-skill")

// Subcommand: epic
//   --title <string>          (required) Epic title
//   --description <string>    Epic description
//   --initiative-id <uuid>    Link to an initiative
//   --actor-id <string>       Who is creating this (default: "claude-code")
//   --actor-type <string>     Actor type (default: "agent")
//   --source <string>         Source identifier (default: "claude-skill")
```

**Implementation approach:**

1. Parse `process.argv` manually (no arg-parsing library — it's ~15 flags max)
2. Generate a UUID for the entity + event
3. Build the ingest envelope matching `IngestEnvelopeSchema`
4. Validate the envelope + payload with the existing Zod schemas (`WorkItemCreatedPayloadSchema` / `EpicCreatedPayloadSchema`)
5. Write JSON to `.taskboard/inbox/<entity_type>-<title_slug>-<short_uuid>.json`
6. Print result to stdout as JSON: `{ "file": "<path>", "entity_id": "<uuid>", "event_type": "<type>" }`

**Key details:**

- The filename uses a slugified title + short UUID for readability in the processed folder
- The script validates its own output before writing — if the envelope doesn't pass Zod, it exits with an error rather than writing invalid JSON that would get rejected
- Uses `process.cwd()` to resolve the `.taskboard/inbox/` path relative to project root
- Exits 0 on success, 1 on validation/write error

**Envelope structure (task example):**

```json
{
  "event_id": "<uuid>",
  "event_type": "work_item.created",
  "occurred_at": "2026-04-11T...",
  "source": "claude-skill",
  "actor": { "type": "agent", "id": "claude-code" },
  "payload": {
    "work_item_id": "<uuid>",
    "kind": "task",
    "title": "Fix login bug",
    "body": "Details...",
    "status": "triage",
    "epic_id": null,
    "parent_id": null,
    "tags": []
  }
}
```

### Phase 2: Claude Code skill — create-task

**New file: `.claude/skills/create-task.md`**

```markdown
---
name: create-task
description: Create a task or bug in the Agent Task System board. Defaults to kind=task, status=triage.
---

Create a work item using the ingest CLI.

## When to use
- User asks to create a task, ticket, or work item
- User asks to file a bug (use --kind bug)
- User says "add this to the board" or similar

## Steps

1. Gather from the user or conversation context:
   - **title** (required): concise summary of the work
   - **body**: detailed description (default: empty)
   - **kind**: "task" (default) or "bug" (only if user explicitly says bug)
   - **epic-id**: if user specifies an epic, look it up
   - **tags**: any relevant tags
   - **acceptance-criteria**: if provided

2. Run the CLI from the project root:
   ```bash
   npx tsx scripts/ingest.ts task \
     --title "<title>" \
     --body "<body>" \
     --kind <task|bug> \
     [--epic-id <uuid>] \
     [--tags <tag1,tag2>] \
     [--acceptance-criteria "<criteria>"]
   ```

3. Confirm creation to the user with the entity ID and title.

## Defaults
- kind: task (ONLY use bug if user explicitly asks for a bug)
- status: triage (always — new items go through triage)
- actor-id: claude-code
- source: claude-skill
```

### Phase 3: Claude Code skill — create-epic

**New file: `.claude/skills/create-epic.md`**

```markdown
---
name: create-epic
description: Create an epic in the Agent Task System board.
---

Create an epic using the ingest CLI.

## When to use
- User asks to create an epic, project, or feature group
- User wants to group related tasks under a parent epic

## Steps

1. Gather from the user or conversation context:
   - **title** (required): epic name
   - **description**: what the epic covers
   - **initiative-id**: if user specifies a parent initiative

2. Run the CLI from the project root:
   ```bash
   npx tsx scripts/ingest.ts epic \
     --title "<title>" \
     [--description "<description>"] \
     [--initiative-id <uuid>]
   ```

3. Confirm creation to the user with the entity ID and title.
4. Ask if the user wants to create tasks under this epic (offer to use /create-task with the new epic-id).
```

### Phase 4: npm script shortcut

**Update: `package.json`**

Add a convenience script:

```json
{
  "scripts": {
    "ingest": "tsx scripts/ingest.ts"
  }
}
```

This allows `npm run ingest -- task --title "..."` as an alternative to `npx tsx scripts/ingest.ts`.

## Data flow

```
1. User in Claude Code: "/create-task Fix the login page redirect"
2. Skill gathers: title="Fix the login page redirect", kind=task, status=triage
3. Skill runs: npx tsx scripts/ingest.ts task --title "Fix the login page redirect"
4. CLI:
   a. Generates UUIDs (event_id, work_item_id)
   b. Builds envelope: { event_type: "work_item.created", payload: { ... } }
   c. Validates with WorkItemCreatedPayloadSchema ✓
   d. Writes to .taskboard/inbox/task-fix-the-login-page-redirect-a1b2c3d4.json
   e. Prints: { "file": "...", "entity_id": "...", "event_type": "work_item.created" }
5. Chokidar watcher (already running if dev server is up):
   a. Detects new file
   b. Validates envelope + payload via validator.ts ✓
   c. Processes via processor.ts → handleWorkItemCreated
   d. Inserts work_item row (status=triage)
   e. Records activity event
   f. Moves file to .taskboard/processed/
6. Board UI auto-refreshes → new task appears in Triage column
7. User clicks "Start Session" on the triage card → terminal tab opens (v0.2.0)
```

## Tests

### Unit

- **CLI arg parsing**: verify title extraction, flag defaults (kind=task, status=triage)
- **Envelope generation**: verify generated JSON matches `IngestEnvelopeSchema` + `WorkItemCreatedPayloadSchema`
- **Epic envelope generation**: verify matches `EpicCreatedPayloadSchema`
- **Filename slugification**: verify special chars, long titles, whitespace handling
- **Validation failure**: verify CLI exits 1 with message when title is missing
- **Kind default**: verify kind=task when --kind not provided
- **Kind=bug**: verify kind=bug when `--kind bug` is passed

## Out of scope

- Bulk task creation (create multiple tasks in one invocation)
- Interactive prompts in the CLI (all args are flags — keeps it script-friendly)
- Creating initiatives from skills (low frequency, use the UI)
- Editing or updating existing tasks from the CLI (use the UI or write a `work_item.updated` envelope manually)
- Auto-assigning agents on creation (tasks start in triage, assignment happens later)
